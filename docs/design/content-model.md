# Модель контента Звуколёта

Документ описывает, из чего состоит контент, как он хранится и как редактор
конструктора собирает пользовательские наборы. Цель: дать разработчику один
источник правды по структурам данных до того, как код закрепит их.

## Три уровня

1. Контраст (contrast): пара звуков, которые ребёнок учится различать,
   например `Ш` и `С`. Контраст задаёт тему занятия.
2. Пара (pair): два слова, которые отличаются одним звуком внутри контраста,
   например `мишка` и `миска`. Пара это единица упражнения.
3. Набор (set): упорядоченный список пар, который взрослый запускает как одно
   занятие. Наборы бывают встроенные (поставляются с приложением) и
   пользовательские (собраны взрослым в конструкторе или загружены из файла).

Связь: контраст содержит пары, набор ссылается на пары контраста.

## Встроенный контент

Встроенный контент лежит в репозитории под `res://content/` и только читается.

### content/contrasts.json

Список контрастов и путь к файлу пар для каждого.

```json
{
  "version": 1,
  "contrasts": [
    {
      "id": "sh_s",
      "title": "Ш и С",
      "sound_a": "Ш",
      "sound_b": "С",
      "description": "Различаем шипящий Ш и свистящий С.",
      "pairs_file": "res://content/pairs/sh_s.json"
    }
  ]
}
```

### content/pairs/<contrast_id>.json

Пары одного контраста. Поле `status` показывает, прошёл ли контент ревью
логопеда: `candidate` значит, что список ждёт проверки, `reviewed` значит, что
проверен. Поле `confidence` у пары (`strong` / `medium` / `weak`) это оценка
разработчика, а не клинический вывод; слабые пары нужны, чтобы логопед видел
кандидатов на замену.

```json
{
  "version": 1,
  "contrast_id": "sh_s",
  "status": "candidate",
  "slp_review": "pending",
  "pairs": [
    {
      "id": "sh_s_01",
      "word_a": "мишка",
      "word_b": "миска",
      "sound_a": "Ш",
      "sound_b": "С",
      "confidence": "strong",
      "hint": "мишка это игрушка, миска это посуда",
      "image_a": "res://assets/images/pairs/sh_s/sh_s_01_a.png",
      "image_b": "res://assets/images/pairs/sh_s/sh_s_01_b.png",
      "audio_a": "res://assets/audio/pairs/sh_s/sh_s_01_a.wav",
      "audio_b": "res://assets/audio/pairs/sh_s/sh_s_01_b.wav"
    }
  ]
}
```

Путь к картинке или звуку может быть пустым: тогда интерфейс показывает
заглушку, а не падает.

### content/sets/<set_id>.json

Встроенные наборы. `pair_ids` ссылаются на пары контраста.

```json
{
  "version": 1,
  "id": "builtin_sh_s",
  "name": "Ш и С: базовый набор",
  "contrast_id": "sh_s",
  "builtin": true,
  "pair_ids": ["sh_s_01", "sh_s_02"]
}
```

## Пользовательские наборы

Пользовательский набор живёт в `user://` и переживает перезапуск.

### user://custom_sets.json

Метаданные всех пользовательских наборов.

```json
{
  "version": 1,
  "sets": [
    {
      "id": "c_ab12cd34",
      "name": "Мой набор",
      "contrast_id": "sh_s",
      "mode_id": "repeat_after_adult",
      "pairs": {
        "p_a1b2c3d4": {
          "word_a": "мишка",
          "word_b": "миска",
          "image_a": "res://assets/images/pairs/sh_s/sh_s_01_a.png",
          "image_b": "res://assets/images/pairs/sh_s/sh_s_01_b.png",
          "audio_a": "res://assets/audio/pairs/sh_s/sh_s_01_a.wav",
          "audio_b": "res://assets/audio/pairs/sh_s/sh_s_01_b.wav"
        }
      }
    }
  ]
}
```

Ключ словаря `pairs` это id пары. Порядок пар в наборе задаёт порядок ключей
словаря; хранилище сохраняет порядок вставки.

Правила:

- id набора начинается с `c_` и генерируется хранилищем;
- `mode_id` это режим, выбранный при создании набора (`listen_choose`,
  `repeat_after_adult`, `name_picture`). Он определяет, как набор играется, и
  виден в редакторе;
- id пары выводится из слов (`p_` плюс короткий хеш пары слов), поэтому
  прогресс по паре не теряется при пересохранении набора;
- пара внутри набора хранит собственные пути к медиа, поэтому набор можно
  перенести в файл и обратно без зависимости от встроенной библиотеки;
- для каждого слова взрослый может приложить своё медиа: картинку (всегда
  сохраняется как `.webp`) и озвучку (`wav`, `ogg`, `mp3` или `m4a`). Своё медиа
  лежит в `user://custom_sets/<set_id>/` и имеет приоритет над библиотечным;
- если своё медиа для слова не задано, репозиторий наборов сначала пробует
  подставить медиа встроенной пары с тем же id, а затем ищет картинку и озвучку
  в библиотеке по тексту слова (регистр не важен). Если слова нет в библиотеке,
  интерфейс показывает слово текстом.

### Конструктор: как взрослый собирает набор

1. На экране «Мои наборы» взрослый нажимает «Новый набор».
2. Открывается выбор режима: «Послушай и выбери», «Повтори за взрослым»,
   «Назови картинку». Выбор режима задаёт `mode_id` будущего набора.
3. Открывается редактор: взрослый вводит пары слов вручную (два поля на
   строку) и задаёт название. Пары не выбираются из готового списка.
4. Для каждого слова можно приложить свою картинку (кнопка «Картинка»),
   записать голос с микрофона (кнопка «Записать»), выбрать готовый звуковой
   файл (кнопка «Файл»), послушать (кнопка «Слушать») и убрать (кнопка
   «Очистить»).
5. При сохранении своё медиа сохраняется в каталог набора; для слов без своего
   медиа картинка и озвучка подставляются из встроенной библиотеки по тексту
   слова; чего нет ни там, ни там, остаётся пустым.
6. Набор можно сразу запустить кнопкой «Играть» на его экране: игра
   использует `mode_id` набора.

Режим «Повтори за взрослым» работает и без медиа: ребёнок повторяет слово за
взрослым. Режимы «Послушай и выбери» и «Назови картинку» требуют картинку и
озвучку, поэтому для них важно, чтобы введённые слова были в библиотеке.

### user://custom_sets/<set_id>/

Своё медиа пользовательского набора. Имена файлов выводятся из базы строки и
стороны слова: `<base>_a.webp`, `<base>_b.webp` для картинок и
`<base>_a.<ext>`, `<base>_b.<ext>` для озвучки. База строки это id пары
(`p_` плюс хеш слов); пока слова не введены, база берётся от времени. Запись
одного и того же слова ложится в тот же файл, копий не плодится.

Картинка всегда сохраняется как `.webp` (ужимается до 1024 px по длинной
стороне). Озвучка хранится в исходном формате: запись с микрофона как `wav`,
выбранный файл как `wav` / `ogg` / `mp3` / `m4a`. В веб-сборке `m4a`/`aac`
перекодируются в `wav` до сохранения.

Медиа, подставленное из встроенной библиотеки, хранится как путь `res://` и в
каталог набора не копируется. При экспорте в `.zvset` пути `res://` читаются и
упаковываются в архив, поэтому переносимый набор самодостаточен. Кнопка
«Очистить» удаляет только файлы своего медиа внутри каталога набора.

## Формат файла набора .zvset

Файл набора это ZIP-контейнер. Расширение `zvset`, имя манифеста
`manifest.json`.

Манифест:

```json
{
  "format": "zvukolet-set",
  "version": 1,
  "name": "Мой набор",
  "contrast_id": "sh_s",
  "pairs": [
    {
      "id": "sh_s_01",
      "word_a": "мишка",
      "word_b": "миска",
      "image_a": "media/sh_s_01_a.png",
      "image_b": "media/sh_s_01_b.png",
      "audio_a": "media/sh_s_01_a.wav",
      "audio_b": "media/sh_s_01_b.wav"
    }
  ]
}
```

Пути медиа внутри манифеста относительные, от корня архива. Импорт:

1. читает ZIP, проверяет манифест по формату и версии;
2. создаёт новый пользовательский набор с новым id;
3. копирует файлы медиа в `user://custom_sets/<new_id>/`;
4. переписывает пути в записи набора на `user://`.

Пределы (совпадают с проверками при импорте):

- `MAX_PACKAGE_BYTES` = 25 МБ: размер самого файла;
- `MAX_TOTAL_UNCOMPRESSED_BYTES` = 60 МБ: суммарный размер распакованных
  файлов;
- `MAX_FILES` = 80: число записей в архиве;
- `MAX_MANIFEST_BYTES` = 256 КБ: размер манифеста;
- `MAX_PAIRS` = 40: число пар в одном наборе.

## Открытые вопросы

- Список пар `ш-с` помечен `candidate`: нужен ревью логопеда. Часть пар
  слабые (служебные слова `наш`/`нас`, редкие слова `сайка`, `шило`).
- Своё медиа добавляется в конструкторе. В веб-сборке запись с микрофона и
  перекодирование `m4a` зависят от браузера; на Android и десктопе запись идёт
  через нативный захват.
- Несколько контрастов в одном наборе пока не поддерживается: набор привязан к
  одному контрасту.
- Режимы «Послушай и выбери» и «Назови картинку» требуют медиа: для слов, которых
  нет в библиотеке, они показывают слово текстом.
